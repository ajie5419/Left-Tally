## 本批操作

项目部在工单库直接填写工单号、客户名称、数量、交期，可选项目和事业部，直接保存，无须指定生产项目负责人。生产项目负责人由生产部后续指定；未指定显示“待生产部指定”。同型号两台设备分别建两张工单，刷新和重新读取保留各自记录。只读演示身份可以查看，不能新建。

工单是本系统数据，不要求 QMS 预先有同号工单。借鉴 QMS 的字段与操作做法，不宣称技术长度等参数与真实 QMS 表结构逐项相同；以下长度是本系统明确的工程约束。统一身份现已通过两仓真实源码与隔离账号联调，人员目录及质量结果仍未接入；不把隔离测试账号当作正式业务人员配置。后续修改已有工单、客户交期变更及历史更正按对应业务场景实施，本批提供新建和查看。

## 字段规范

| 业务字段       | API 字段 / 存储类型                    | 必填与校验                                                   | 含义                                                                   |
| -------------- | -------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 内部编号       | `id` / VARCHAR(36)                     | 服务端生成 UUID，客户端不可指定                              | 稳定标识，不用可读工单号代替内部关联                                   |
| 工单号         | `number` / VARCHAR(128)                | 必填，去首尾空格，1–128 字符，数据库唯一约束                 | 保留用户输入大小写；精确区分大小写，不擅自变更编号规则                 |
| 客户名称       | `customer` / VARCHAR(200)              | 必填，去首尾空格，1–200 字符                                 | 本系统建单录入，不假称来自客户主档或 QMS                               |
| 数量           | `quantity` / INTEGER                   | 必填，数值整数 1；数据库 CHECK 同样限制为 1                  | 一台设备一张工单，单位为“台”；不用浮点、字符串强转或未知值补零         |
| 交期           | `dueDate` / DATE                       | 必填，有效公历日期 YYYY-MM-DD；范围 1000-01-01 至 9999-12-31 | 业务日期，不带时区；不与创建时间或内部计划日期混用，不擅自禁止历史日期 |
| 项目           | `project` / VARCHAR(200) NULL          | 选填，最多 200 字符                                          | 未填、空白统一保存 null，展示“未填”；本批不冒充已建立合同及项目主档    |
| 事业部         | `division` / VARCHAR(128) NULL         | 选填，最多 128 字符                                          | 未填保持 null，不默认填某个部门                                        |
| 生产项目负责人 | `productionLeadId` / VARCHAR(128) NULL | 建单请求不接受该字段；新建为 null                            | 由生产部指定；未指定显示“待生产部指定”，不默认填某个人                 |
| 创建人         | `createdBy` / VARCHAR(128)             | 服务端由已验证会话取得                                       | 请求不得自行指定，不作为公开工单字段返回                               |
| 创建时间       | `createdAt` / DATETIME(3)              | 服务端生成 UTC 时间，响应 ISO 时间                           | 毫秒精度，与日期型交期分开                                             |

前端和后端使用共享校验契约；后端是权威。未知字段如伪造创建人、角色和 QMS 工单引用被拒绝。数据库使用 utf8mb4，字段长度与接口上限对应。并发同号创建只成功一次，其余返回“工单号已存在”。保存失败保留输入，修正后可以重试。

## 打开页面与演示步骤

工程根目录执行，需本机容器服务运行：

```bash
GC_NODE="$PWD/.tools/proto-home/tools/node/24.21.0/bin/node"
"$GC_NODE" scripts/toolchain.mjs pnpm build
"$GC_NODE" scripts/toolchain.mjs pnpm demo:b01
```

打开终端输出的 `B01_DEMO` 地址。脚本创建专用临时 MySQL；进程运行期间刷新不会丢失，正常退出后清理，下次启动为空库。测试用虚构数据，不输入真实业务信息。

1. 选择“项目部演示账号”，填写 GD-01、示例客户、数量 1、交期 2026-11-20、项目“某桥梁设备合同”、事业部“示例事业部”后保存，不填写负责人。
2. 再填 GD-02、相同客户项目、交期 2026-11-25，事业部留空后保存。
3. 刷新页面：两条工单及各字段独立保留，GD-02 事业部显示“未填”，两条均显示“待生产部指定”。
4. 再用 GD-02 保存：提示工单号已存在，列表仍为两条；输入其他工单号后可以重试。
5. 切换“技术部只读演示账号”：工单可查看，新建表单隐藏，直接请求写接口也被拒绝。
6. 数量填 0、2 或小数，交期无效、必填空白、字段超长均不应保存。人员不可读取时仍可新建和查看工单；项目部在建单请求中夹带负责人被拒绝，故障与直接请求由自动测试覆盖。

## 正式运行接口边界（2026-10-15 历史记录）

用户要求接口可延续到实际部署，本轮收敛了演示与正式运行边界：

- 页面统一读取 `/api/session`，服务端返回当前人员、权限及登录入口；正式模式没有演示身份选择器，也不请求演示身份列表。
- 工单接口逐请求验证身份与查看／新建权限；故障明确返回不可用，客户端身份头、角色或创建人字段不能赋予权限。
- 演示登录只由演示组合显式挂载，正式组合不注册 `/api/demo/*`，复用同一业务用例和 MySQL 仓储。
- 独立 `start:api` 入口使用持久数据库；`db:deploy` 显式执行迁移。正式启动检查配置、工单表与会话表，不创建或清空临时库；外部 HTTPS origin 与内部代理地址分开校验。
- `/openapi.json` 发布当前真实接口，包含登录、回调、退出及独立会话约定；生产部指定负责人接口仍未开放。

接入合同、环境变量、构建／迁移／启动顺序和 Caddy 示例见 [API 运行说明](../apps/api/README.md)。`apps/api/src/runtime-adapters.ts` 已接真实 QMS 身份桥：员工通过 QMS 原登录及固定授权页确认，履约系统建立独立持久会话；不接收 QMS 业务令牌、不复制密码、不按部门或角色名称自动赋权。缺少受控配置时拒绝启动。退出只撤销履约会话及对应集成凭证；账号停用在下一次身份核查拒绝。

真实跨系统浏览器已覆盖无 QMS 菜单权限员工登录、显示本人、授权建单、退出和停用后的页面清理，使用真实 Nitro 路由及中间件、授权页、履约前端与 API、隔离数据库及 HTTPS。正式 HTTPS 校验未放宽。Compose 镜像及编排、生产证书与代理发布、分页筛选、生产部指定负责人仍未交付或验证。原有演示进程及用户测试记录未重启或清理。
