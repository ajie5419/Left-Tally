# Grand Comptroller 关键业务设计

版本：1.0。日期：2026-10-13。状态：设计稿，无应用实现或运行验收证据。

依据：[需求基线](需求基线-2026-10-13.md)。本文将已确认规则转换为对象、操作、校验和验收目标。字段名、分层、计算步骤及界面组织是工程设计选择，不能当作已经存在的企业制度或已接通的接口。

## 1. 设计原则与交付边界

以工单隔离数量、资料和执行记录，以稳定 ID 关联对象，编号及名称仅作展示。不同工单的相同图号不合并。同一图号在不同装配位置、版本或计量范围中不能仅凭名称自动去重。

正式约束由后端用例执行，前端显示同一原因；不能只禁用按钮。用例负责权限、版本、状态、证据与事务，路由只负责输入、调用、输出。2026-10-13 用户已确认 TypeScript、Vue 3 + Vite + Ant Design Vue、Vue Router + Pinia、Hono + Node.js 24 LTS、Zod + OpenAPI、MySQL 8.4 LTS／InnoDB + Prisma、pnpm workspace、Vitest + Playwright、Docker Compose + Caddy，采用模块化单体及独立履约数据库。详见[技术栈与工程架构](技术栈与工程架构-2026-10-13.md)。具体依赖版本及兼容性在工程初始化时验证并锁定；选型确认不代表已经安装或实施。

同一套账号及 QMS 主数据采用适配边界，正式财务和库存仍归 K3。不将 QMS Schema、供应商资格判断或密码复制进履约系统作为另一套权威来源。

## 2. 核心对象与关系

| 对象 | 主要关联及建议字段 | 约束 |
| --- | --- | --- |
| 项目及合同节点 | 合同依据、销售、工单、约定节点类型／范围／日期、客户确认记录 | 一项目一合同、多设备工单；原承诺、变更后承诺分别留存 |
| 设备工单 | 项目、设备编号、生产项目负责人、任务、批次、验收关系 | 阶段是派生结果，验收完成与阶段进度分开 |
| 计划任务及依赖 | 工单、阶段、责任部门、人、数量范围、计划日期、当前预测或剩余工期、前后依赖及条件 | 区分日期承诺、实际日期、预测；支持部分完成依赖，不强制整批串行 |
| 部件工序需求 | 工单、部件稳定标识、图号、位置或范围、需求数量、单位、工序、资料来源版本 | 从建议确认建立；不同图号或单位不能相加算百分比 |
| 任务包／执行安排 | 工单、工序、执行方、图号明细、分配数量、跟进人、要求及调整关系 | 一包一个工单、一道工序、一个执行方；拆分归同一需求 |
| 进度事实 | 安排、数量范围、首次开工／首次完工、发生时间、录入时间、人、来源、预计及确认事件 | 完工与返工分开；未知开工数量可空，不能默认零 |
| 交接批及明细 | 工单、路线、源安排、目的安排、交出／接收方、日期、图号、单位、收发记录、送货单关联 | 按工单拆记录，可共用附件；收发事实独立 |
| 流转关联及更正 | 返回明细、原送出明细、分摊数量、核实状态、原记录、更正原因 | 可关联多批，未知映射不自动按先送先回猜配 |
| 返工任务 | 原任务及范围、QMS 不合格依据、执行方、事实、重新检验关联 | 工作量独立，原件不重复计成新增产出 |
| QMS 质量引用 | 外部 ID、工单／图号／工序／安排／批次映射、范围、数量、单位、结果版本、验证时间 | 只是来源引用；不可篡改 QMS 判定 |
| 采购需求、到货及供给分配 | 工单、K3 外部标识、QMS 供应商引用、需求／预计／实际日期、数量单位、分配记录 | 分配是意图，不等于库存预留或实际领料 |
| 配套关系与可用依据 | 总成版本、零件标识、每套用量、单位、来源及可用数量、质量和占用依据 | 技术维护配套，理论计算与现场核实分开 |
| 资料版本及下发／接收 | 工单、图号、资料类别、版本、下发人时间、接收部门各自的确认记录 | 首版文件仍线下，不能默认有在线附件 |
| 技术变更及暂停 | 资料版本、受影响任务及数量范围、技术要求、暂停生效时间、落实及恢复确认 | 局部暂停，解除不自动取消 QMS 门禁 |
| 问题、协调措施及提醒 | 影响任务、部门、执行人、结论、截止、延期申请、风险、通知及升级结果 | 问题关闭、措施完成、现场恢复分别维护 |
| 发运清单及批次范围 | 工单、技术总清单、批次明细、预计、实际发出、接收、首批范围版本 | 首批范围修改不能修改正式合同范围 |
| 验收文件及设备结果 | 文件依据、销售、每工单验收结果及日期、遗留事项 | 一文件多工单，不能一次签字把未验收设备自动完成 |
| 项目关闭及遗留承接 | 项目核对记录、每项责任人／期限／承接部门、关闭时间 | 关闭后待办和逾期提醒继续有效 |
| 身份引用及履约授权 | QMS 人员／组织／供应商 ID、角色、工单责任、领导配置、移交记录 | 主档案来自 QMS，履约职责本地维护，停用不删历史 |

部署前需按实际数据库和 QMS 契约细化字段类型、精度、唯一约束与索引。本稿不生成占位应用或未经验证的数据库迁移。

## 3. 数量、批次与事实

### 3.1 首次产出、返工与转派

常规同单位、同范围下，所有有效执行安排的分配数量不得超过确认需求。转派先核实未开工范围，事务中同时减少原安排、建立新安排及关联更改原因，总需求不增加。未开工量不能仅用“分配减完工”计算。

首次完工累计不超过有效分配；开工数量已可靠记录时再验证“完工不超过已开工”。返工是原范围的额外执行工作，不重加首次产出。更正追加关联记录，当前有效投影按有效更正计算，原事实仍可查看。

不预设单件都有序列号：优先批次或可辨识数量范围，细粒度由真实单据决定。重复送回、重复检验或重复点击均不能生成新的物理产出；幂等键防同一次提交重放，物理范围关联防不同记录重复计算，两者缺一不可。

### 3.2 交出、接收及差异

交出记录必填工单、图号、工序、交出方、接收方、交出日期、数量，工程上同时要求有效单位、对应安排或明确的待关联范围。接收登记要求实际收到日期、数量和确认来源；未知接收保持空，不写成零。

未取得接收反馈显示“接收待确认”，不能用“交出减零”直接判为丢失。接收部分确认后显示已交出及已确认收到，待核实差额需结合双方反馈说明，不自动断言在途或丢失。确属多收、少交、在途或录错时分别补核实结果；不把差异关闭自动转换成数量相等。

返回先关联执行安排，送出批次可一对多映射并记录分摊数量；已确认的匹配不得超出对应有效送出范围。无法核实批次时记录实际收到，但标明批次对应待确认。需要明确批次放行的后序仍不得凭模糊映射开工。

厂内交接、外协回厂、外协直送保留真实路径。回厂待检允许登记接收，不要求接收小于合格；直送不是未开工任务转派。位置是已证实流转的派生信息，交出而未收到的范围不能自动归到下家。

### 3.3 部分合格后开工

准入必须核对同一工单、任务范围、执行安排／目的执行方、单位与适用放行节点。可开工范围是“已确认收到、在该接收方实际可用、对应有效合格结果覆盖、未被其他开工消耗、没有有效暂停”的交集，不能简单取两个总量的最小值。

例如合格 3 件和收到 3 件可能来自不同批，未映射前不能推定 3 件可开工。同批 6 件中 3 件满足条件，允许这 3 件先开工；未开工余量等待。此类受控操作需记录本次范围或数量，不改变一般在制任务每日开工数量非必填的决定。

## 4. 状态、权限与门禁

### 4.1 状态采用独立维度

| 维度 | 建议显示 | 派生依据 |
| --- | --- | --- |
| 工作进展 | 未开工、在制、首次加工完成；另列返工中／返工完成 | 有效首次事实、数量及返工记录 |
| 问题影响 | 无已记录影响、部分受阻、暂停、待检等具体原因 | 问题影响范围、质量条件及有效暂停 |
| 信息时效 | 最新已确认、待确认，保留上次记录时间 | 负责人主动确认及工作日时效 |

“已完工”不等于合格、收到或可转序；“问题已关闭”不等于已经恢复。状态文案是设计选择，不能仅凭枚举跳转改写实际事件。

### 4.2 操作校验矩阵

| 操作 | 前置条件 | 不满足时 |
| --- | --- | --- |
| 新增派工 | 有效职责、工单工序一致、数量可分配、执行方当前有效资格可核实 | 拒绝写入并说明原因；未知资格不默认为可用（工程安全选择） |
| 未开工转派 | 核实范围、原记录版本一致、非已开工、同需求数量守恒 | 拒绝超量或冲突，要求刷新／核实 |
| 正式下道开工 | 依赖条件、本次范围收到且实际可用、适用质量放行有效、无暂停 | 拒绝正式开工；允许独立登记违规事实异常 |
| 分批完工 | 有效安排及范围、累计不超量、无覆盖该发生时间的暂停 | 拒绝新的正常完工；历史事实按事件时间核对 |
| 交接接收 | 实际接收结果及来源、对应图号单位 | 允许回厂待检；差异不覆盖原数量 |
| 普通问题关闭 | 责任部门负责人、处理结论 | 不要求项目负责人额外关闭审批 |
| 暂停解除 | 技术落实结论、生产项目负责人现场恢复确认 | 保持暂停；普通问题关闭不能解除 |
| 销售验收登记 | 授权销售、签字依据、明确工单及验收结果 | 只完成通过的工单，遗留不阻止工单完成 |
| 项目关闭 | 项目部核对全部工单验收、合同范围；每项剩余遗留有承接人、期限及部门 | 条件缺失不关闭；有完备承接允许关闭 |

质量结果在服务端按正式契约核实，QMS 无法连接时禁正式开工。历史缓存可以展示并标明时间，不能作为断联后继续放行的替代依据。撤销或更正后历史开工不删除，新受影响范围阻止推进并记录风险。

违规提前开工异常应保存实际时间、任务、数量范围、原因、责任人及后续处置。取得放行后记录正式允许开工时间及相关异常，不能把现场实际时间改成放行后日期，也不能借异常登记绕过门禁。

暂停判断使用发生时间和可信变更记录，暂停前事实可补录，录入时间仍保留。暂停后违规已发生事实走异常证据，不能通过人为倒填时间获得正常状态。历史补录证据细则列为 E02 核实，不新增审批。

所有写入按同一责任和门禁执行；代录、更正没有质量、暂停或数量限制的豁免。金额限制需在服务端响应契约中落实，不是仅隐藏列。

## 5. 自动阶段判断

按阶段的有效计划任务和事实推导：有开工／执行事件且阶段必需范围尚未完成，视为进行中。制造尚在进行且总装已开始，显示“部件制造、总装并行”。阶段任务清单不完整、缺必要事实时显示该阶段信息待确认，不把未录入当完成。

阶段可包括技术准备、工艺准备、采购、部件制造、总装、技术调试、发运、现场执行；具体任务归阶段由计划维护。已结束阶段保留在历程，不继续当成进行中。暂停、返工等作为该阶段影响信息，而不是新造互斥阶段。

客户验收通过的履约完成来自销售验收事件，不能从所有生产任务完成自动推导；履约完成后仍显示遗留事项及后续服务进展。阶段名称和任务归属是可配置设计，不由单条部件完成触发整机完成。

## 6. 预计首批发货及合同风险

### 6.1 输入与范围

技术总清单形成设备的发运范围依据。生产项目负责人编排批次，项目部首次确认首批及必要制造、合格、包装、装车等任务关联。其后生产项目负责人或项目部调整范围，立即重算，记录原因及范围版本；不追加逐次审批，不缩减合同范围。

计算对象是“预计首批发货日期”，不是准备完成、装车完成、全部发完、客户到货、装船或验收。首批清单还需关联实际运输／发出准备节点，不能只取加工任务日期。

输入包括有效范围版本、依赖类型及满足范围、实际完成、当前可靠预计、剩余自然日工期、外部等待节点和暂停恢复依据。项目部维护关系；各部门维护自身日期或工期。不把“最近未更新”自动解释为实际延期，但旧预测不当作最新可靠输入。

### 6.2 工程计算步骤

1. 从首批发出节点向前提取必要任务及批次数量依赖，排除未属于首批的后续工作；检查循环、缺边、未关联任务和范围重复。
2. 用实际满足范围解除相应依赖；部分可用且满足首批范围时，不要求前序整批完成。
3. 对未结束节点，取有效预计完成日期，或有基准的剩余自然日工期。剩余天数固定关联当次录入的基准日期，重算不能每天把同一个旧剩余天数重新加到今天。未完成但预计日期已经过去时提示核实，不静默当作已完成，也不自动顺延。直接日期与剩余工期换算同时提供但矛盾时提示核实，不静默任选。
4. 在完整依赖图上按拓扑顺序计算最早可达到日期。后序依据前置就绪和自身剩余工期推算，直接预计早于必要前置时不采信为合法结果。
5. 必需输入未知、循环、无限期暂停、没有范围映射或关键当前预测已待确认时，输出“待评估”和缺口；保留上次预测另作历史参考。
6. 保存范围版本、计算基准、输入版本、结果状态及影响路径，方便解释重算原因。依赖、进度、首批范围、放行影响或预测基准变化触发重算。

设计采用开始／完成条件和明确的部分范围依赖，不擅自把所有任务都转成“整批完工后才能开始”。公式示意：对于明确的完成后开始关系，后序最早完成为“必要前序就绪日期 + 后序剩余自然日工期”，还需同时满足自身可靠预测及其他明确约束。日期加法按本地业务日期定义，不通过毫秒加 24 小时处理时区日期；录入 10 月 13 日“还需 3 天”得到 10 月 16 日。

这是一套预测设计，尚未用真实工单或程序验证。不存在自动资源优化或自动排产；无可靠输入不兜底填标准工期。

### 6.3 合同节点单独判断

合同节点保存类型、范围、承诺日期、客户确认依据及对应当前预计／实际。首批发货节点可以采用首批预测；全部发完、到货、装船等采用匹配的有效预计或实际，不新增这些节点的自动预测能力。

| 情况 | 风险显示 |
| --- | --- |
| 同范围、同节点的可靠预计晚于承诺 | 已识别交期风险及影响任务 |
| 已实际完成且实际晚于承诺 | 实际逾期，不能因之后改计划抹掉 |
| 没有匹配节点预计，尚未超过承诺 | 待评估，明确缺口，不显示按时 |
| 必需实际节点尚未完成且承诺已过 | 显示承诺到期未完成；若实际信息未核实，同时标待核实 |
| 首批按时、末批预计未知 | 首批预计按时；全部交付待评估 |

上述逾期展示是对“按实际合同节点判断”的工程展开，不代表系统已执行。风险首次出现、加重、措施到期未完成触发通知；风险加重以同范围节点延误加深或新增必要阻塞等可解释事件识别，具体阈值需配置验证。减少首批范围产生的改善单列原因，不能自动结清其他批次或合同风险。

## 7. 理论齐套与采购供给

技术维护每套用量及装配版本。理论计算在同一工单、总成版本、用途范围中，对每个必需零件使用“已知实际可用且满足适用质量条件、未被同范围其他需求占用”的数量。到货总量、项目部分配意图和实际可用量分别保存。

对可明确换算到件／套的组成件，理论可做套数为每个必需零件“可用数量 ÷ 每套用量”的整数下界的最小值。例如每套 2 支座、1 连接板，可用 7 支座和 4 连接板，理论为 3 套。首次计算不得自动在 K3 做领料或预留。

缺零件、未知数量、单位不兼容、版本关系不完整或占用依据不清时显示无法计算及缺口，不把未知当零，不忽略缺项。合法的已知零才形成 0 套；不同版本或单位不直接相减。

理论套数与生产项目负责人现场确认数量独立。现场核实前系统不得把理论套数当作开工许可；确认时说明核对来源及偏差。重复分配须防止同一可用范围被多个工单／总成同时算作可独占物料；在 K3 不接入时期，只能对本系统已记录的用途分配做防重复，不能宣称掌握实时库存。

采购 Excel 导入采用预览、差异核对及确认，保留文件来源及业务行映射。项目部登记部分到货的分配数量；采购、生产看同一事实来源。实际 K3 库存、领料或检验仍引用原系统责任，不用履约分配记录伪造正式账。

## 8. 资料、变更与问题闭环

资料版本登记类别、编号、工单／图号、版本、下发时间，接收按部门独立记录。图纸文件继续线下交付，资料元数据可从 BOM 等关联，不因一个部门接收就把所有部门改为收到。新图下发、接收与旧图收回／作废的执行情况分别记录，不能因为新图已发就宣称旧版已处理。原任务引用固定版本，最新版本另提示。

导入识别工单、部件身份、来源版本和原业务关系，不仅按图号匹配；结果分新增、变更、疑似重复及无法识别。分批 BOM 和最终总表属于同一需求的候选来源，不能每次追加总需求。已派工／开工变更进入明确影响处理，不能用导入覆盖原执行。

技术变更指明任务及数量范围、继续／暂停／返工要求、资料版本、处理记录。资料未收到不统一停工；明确的暂停按第 4 节控制，技术落实与现场恢复两项具备后解除。质量结果还未具备时继续受 QMS 门禁约束。

普通问题由责任部门安排处理、负责人关闭，生产项目负责人另更新恢复与预测。现场质量问题由现场确认及证据交品质，在 QMS 关闭，本系统只引用。不能通过复制 QMS 问题再关闭另一个本地问题改变质量状态。

协调措施记录执行人、责任部门及截止时间。到期未完成自动向各部门分管领导升级，同步执行人、部门负责人和项目部。设计需有通知幂等、收件结果及失败重试；缺领导配置显示配置异常，不写成升级成功。延期只有项目部确认才生效，过期后的确认不抹除此前已经发生的升级。

信息待确认的 1 工作日规则需要公司工作日历、调班及明确截止切点。自然日预测不复用该日历。本轮不假定周末一律休息，也不把工作日提醒悄悄换为 24 小时。

## 9. 客户、验收和关闭

销售维护客户变更候选及协议证据，协议确认前不更新正式范围。客户承诺日期由销售根据客户依据变更，项目部再调整内部计划。进场客户侧与实际执行侧分别维护，现场采用汇总关键节点方式。

销售登记签字验收依据，逐工单记录通过与未通过；通过的工单在同一业务事务中成为履约完成，不要求项目部审批。不将整份文件对应的所有设备默认验收通过，客户条件性表述需据实际文件核对。

遗留另设责任人、期限、承接部门。项目部手动关闭项目时核对工单及合同范围，可带有完整承接的遗留事项关闭。关闭不取消遗留待办、逾期或领导升级，历史工单继续关联。验收资料撤销、更正等高影响例外待制度核对，不能套用普通数量更正静默撤销完成。

## 10. QMS 统一身份和数据集成

QMS 为供应商、外协、内部组织及人员班组的权威来源，本地只保留稳定外部引用、显示快照、时效及履约职责。资格或账号停用是显式状态，旧任务及责任历史保留；停用外协禁止新增派工，既有任务标风险而不自动全部取消。

账号采用统一身份，认证适配要求验证身份、来源和会话有效性，再应用本系统权限。禁止读取或复制密码、在前端直连 QMS、信任未经验证的跳转身份。具体认证协议、停用传播时限、主数据同步及质量接口由 E03–E05 验证，本稿不虚构接口路径。

权限需核对对象职责、代录原因和行为类型，两个系统同账号不代表权限相同。人员停用后由部门负责人或项目部移交任务、问题和待办；原行为人保留。不能把部门领导提醒接收身份自动升级成所有写入权限。

QMS 结果至少能匹配工单、图号／部件、工序／检验节点、批次范围、单位、结果版本、有效状态和撤销变化，才可用于正式放行。只匹配供应商或图号总数不足以支持 Q24。建立契约、失效和重试验收后，才能宣称实时门禁有效。
