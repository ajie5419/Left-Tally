## 1. 已确认技术栈

| 层次 | 已确认选择 | 用途及边界 |
| --- | --- | --- |
| 开发语言 | TypeScript，启用严格类型检查 | 前端、后端和共享契约 |
| 前端 | Vue 3 + Vite | 电脑端为主，手机浏览器支持查看和少量更新 |
| 界面组件 | Ant Design Vue | 表格、表单、日期和弹窗；沿用现有原型的视觉方向 |
| 路由与状态 | Vue Router + Pinia | 页面导航及客户端状态；服务端业务事实以接口结果为准 |
| 后端 | Hono + Node.js 24 LTS | REST API，采用 Node.js 适配方式 |
| 接口校验与说明 | Zod + OpenAPI | 输入输出约束及接口文档；业务门禁在后端执行 |
| 数据库 | MySQL 8.4 LTS，InnoDB | 履约系统独立数据库和访问账号 |
| 数据访问与迁移 | Prisma | 具体兼容版本初始化时验证锁定；7.x 仅为候选版本线 |
| 工程组织 | pnpm workspace | 前后端及共享契约统一管理；开发工具按用户规则通过 proto 管理 |
| 测试 | Vitest + Playwright | 业务规则及浏览器流程；数据库集成测试使用 MySQL |
| 部署 | Docker Compose + Caddy | 容器编排、静态文件服务及 API 反向代理 |

上述版本线是已确认的选型方向，不是已安装版本清单。工程初始化时验证组合兼容性，锁定具体版本及 lockfile；不以自动跟随最新版本代替验证。

## 2. 已确认架构边界

采用模块化单体：一个后端服务按业务模块组织，前后端分开构建，共用 pnpm workspace。数量转派、批次消耗、质量准入和历史更正由后端用例处理。

履约系统与 QMS 保持独立数据库、Schema、迁移和访问账号，通过接口关联人员、组织、供应商和质量引用。不跨系统直接修改数据表，不复制密码。统一账号目标已确认；具体认证协议、账号停用传播和质量结果撤销传播仍须取得接口证据。

首版不将 Redis、消息队列或通用工作流引擎列为必需组件。后续新增这些依赖时，须有实际需求或验证证据支持，并更新本选型记录。

## 3. 工程组织建议

以下目录是实施建议，不表示目录或应用已经建立：

```text
apps/
  web/
  api/
packages/
  contracts/
```

后端模块内区分路由、业务用例、数据访问和外部系统适配。共享契约维护接口结构、校验和稳定编码，不直接把数据库对象暴露给前端。

## 4. 实施时必须验证的约束

- 转派、分配及批次消耗使用事务、必要的锁和约束保护；不能先查询总量，再无保护地写入。
- 版本条件更新用于发现旧页面覆盖；幂等记录和唯一约束用于拒绝提交重放。多人并发必须实际测试。
- 数量使用精确数值类型，明确精度、单位和换算；未知保持为空，不填成零。
- 合同日期与事件时间分开建模；自然日与工作日分别遵循已确认规则。
- 进度更正、暂停、交接和资料版本保留来源和历史；业务审计不依赖运行日志替代。
- 首批预测、理论齐套和质量准入在后端执行，浏览器展示结果及原因。
- 数据库集成测试使用 MySQL；不以其他数据库的通过结果证明 MySQL 事务或并发安全。
- 正式质量准入需核实 QMS 结果及范围；接口不可用不能默认放行。
