# 第一条业务链开发计划

日期：2026-10-15。状态：计划，待执行。验收标准见[第一条业务链验收场景](验收场景-第一条业务链-2026-10-15.md)（已确认，下文 S1–S17 指其中场景 1–17）。规则依据见[需求基线](需求基线-2026-10-13.md)、[关键业务设计](关键业务设计-2026-10-13.md)、[工程治理与门禁基线](工程治理与门禁基线-2026-10-13.md)、[技术栈与工程架构](技术栈与工程架构-2026-10-13.md)。

范围：建工单（引用 QMS 工单）→ 部件工序登记 → 派工任务包 → 进度、阻塞与更正 → 首页、明细与执行方视图。交接与外协、质量放行、转派、齐套、首批预测、资料、问题升级、验收关闭、统一登录、Excel/BOM 导入不在本链。

每项完成须满足：后端权威实现、对应场景测试通过、`pnpm verify` 全部步骤退出 0。不写时间估算。

## 1. 开工前需核实或批准

- [ ] **QMS 工单只读接口**：确认 `GET /api/qms/work-order` 的认证方式、只读账号、字段（工单号、客户、项目、事业部、数量、交期、状态）及分页；接口不可用时页面显示"无法读取"，不虚构工单。依据确认结论 1、E05
- [ ] **QMS 工单数量与"每台一单"的对应**：QMS `work_orders.quantity` 可能大于 1，确认一台设备是一张 QMS 工单，还是一张 QMS 工单对应多台设备
- [ ] **Prisma 版本锁定**：验证 Prisma 7.x + `@prisma/adapter-mariadb` 在 Node 24 与 MySQL 8.4 上的组合，锁定版本，更新 `config/compatibility.json`
- [ ] **门禁阶段切换**：从 BOOTSTRAP 切到 CORE，登记本链必需业务测试套件；按治理基准第 3 节由用户批准后修改受保护配置，实现者不自行切换

## 2. 数据模型与迁移

- [ ] Prisma Schema：工单引用（QMS 工单号、生产项目负责人）、部件（图号、名称、需求数量）、工序、执行方、任务包与明细、进度事件、阻塞、确认记录、更正记录
- [ ] 数量用精确数值类型；开工数量等未知值存空，不存 0
- [ ] 合同交期（来自 QMS）与事件时间分字段；进度和更正只追加，不覆盖原事实
- [ ] 首个迁移；`check:migrations` 覆盖空库建表和迁移完整性
- [ ] 演示账号与角色（项目部、统一派工负责人、生产项目负责人、生产负责人、只读部门），明确标为演示用，仅在测试/演示环境加载

## 3. 工单与部件（S1、S2）

- [ ] 契约：工单、部件、工序 DTO 与 Zod 校验（`packages/contracts`）
- [ ] QMS 只读适配器（infrastructure），路由不直接请求 QMS
- [ ] 建工单：选择 QMS 工单号并指定生产项目负责人；同型号多台各一张工单，不合并
- [ ] 部件工序手工录入；同图号在不同工单独立计数
- [ ] 测试：S1、S2；QMS 不可用时拒绝建单

## 4. 派工安排（S3–S7）

- [ ] 任务包：限同一工单同一工序，保存即生效，无下达/接收步骤（S3）
- [ ] 跨工单混包拒绝，返回明确原因（S4）
- [ ] 有效安排数量不超过需求；事务加锁，真实 MySQL 并发测试证明不超分配（S5）
- [ ] 完成要求支持具体日期或仅先后顺序，不虚构日期（S6）
- [ ] 提前指定执行方只显示"已指定"（S7）

## 5. 进度、阻塞与更正（S8–S13）

- [ ] 在制登记与"还需 N 天"，预计完成按自然日计算；开工数量未填显示"未填"（S8）
- [ ] 分批完工累计，不超过有效安排；超出拒绝（S9）
- [ ] 阻塞登记含部件、原因、跟进人；生产项目负责人可标"已恢复"（S10）
- [ ] 批量"确认未变"：先列出范围，只刷新确认时间（S11）
- [ ] 超过一个工作日未确认显示"待确认"和"上次记录"的预计，不显示延期；工作日第一版为周一至周五，时间基准显式传入（S12）
- [ ] 更正：写原因，追加记录，原值与原因可查（S13）
- [ ] 版本条件更新与幂等键：旧页面覆盖和重复提交被拒绝

## 6. 首页与查看（S14–S17）

- [ ] 首页每台设备一行：阶段、卡在哪（部件与原因）、谁在跟、信息是否最新、**逾期时间**（已过 QMS 交期且未完成时显示逾期天数）；有阻塞的排前（S14）
- [ ] 工单明细：部件、工序执行方、完工数、预计、阻塞、最近确认时间，可返回首页和切换工单（S15）
- [ ] 执行方跨工单视图，每行标明所属工单（S16）
- [ ] 只读角色能看不能改，后端拒绝写入；页面和接口不出现合同金额（S17）
- [ ] 电脑端为主，手机浏览器可查看和少量更新

## 7. 验收

- [ ] 每个场景 S1–S17 各有自动化测试：后端规则单测，权限、事务、并发走真实 MySQL 集成测试，页面流程走 Playwright（桌面与手机尺寸）
- [ ] 绕过界面直接调用接口的拒绝测试（混包、超量、越权写入、超额完工）
- [ ] CORE 阶段 `pnpm verify` 与 CI 通过，证据保存
- [ ] 用虚构演示数据按验收场景逐条走查，由用户确认
- [ ] 如实报告：QMS 真实接口与正式登录未接入的部分不算业务验收通过
